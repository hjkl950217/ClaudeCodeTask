# cct — Claude Code 任务文件夹选择器 · 设计文档

**日期**：2026-08-27
**状态**：待用户审阅
**关联文件**：`../PROGRESS.md`（需求澄清全过程与技术验证证据）

---

## 1. 问题与目标

**问题**：本地有大量文件夹级的 Claude Code 任务，每次要开工得手动复制路径、`cd` 过去、再敲启动命令。同时开多个任务时这套动作重复得让人烦躁。

**目标**：一条命令 `cct` 弹出任务列表，选中即自动切换目录并启动 Claude Code 会话。

**非目标**（明确不做）：

- 不做 Claude Code 会话内的 `/xx` 命令 —— 会话内部没有切换 cwd 的机制，做出来也只能「列出来 + 开新窗口」，比终端命令弱
- 不扫描磁盘找 CLAUDE.md —— 实测 29 个真实用过的任务目录没有 CLAUDE.md（包括本项目目录自己），按它过滤会漏掉一大批
- 不做 SessionStart hook 注册 —— 会话历史里已有全部所需数据，自建注册表是重复劳动

---

## 2. 整体架构

```
cct [关键词]
  │
  ├─ 1. 数据层  Get-CctTasks
  │     扫 ~/.claude/projects/**/*.jsonl
  │     → 每文件读前 50 + 后 50 行
  │     → 提取 cwd / timestamp / custom-title / ai-title
  │     → 排除、聚合、排序
  │     → 输出任务项数组
  │
  ├─ 2. 界面层  Show-CctSelector
  │     全屏可滚动列表 + 实时过滤
  │     → 返回用户选中的项（或 $null 表示取消）
  │
  └─ 3. 执行层  Invoke-CctTask
        Set-Location <任务目录>   ← 必须先切目录
        然后启动 claude           ← 再 resume/continue
```

三层单向依赖，各自可独立测试：数据层是纯函数（输入目录路径，输出对象数组），界面层输入数组输出选中项，执行层输入选中项产生副作用。

**关键约束**：整个工具必须是 **PowerShell 函数**，通过 `Import-Module` 加载进当前 shell。子进程改不了父 shell 的工作目录，做成 .exe 或 `node xxx.js` 会导致 `cd` 只在子进程生效，退出后回到原地 —— 需求直接失败。

## 3. 数据层

### 3.1 数据来源

`~/.claude/projects/<编码后的项目名>/<session-id>.jsonl`

目录名是编码过的（中文和斜杠全变 `-`，**不可逆**），但文件内每条记录都带完整未编码的 `cwd`。所以只读文件内容，不解析目录名。

### 3.2 读取策略：头尾 50 行 + 消息计数早停

实测全库 446 个文件 / 345 MB / 15.3 万行（其中非 agent 会话文件 206 个 / 252 MB）。

**基础字段**（cwd / timestamp / 标题）位置分布：

| 字段 | 位置 | 读头尾 50 行的命中率 |
|---|---|---|
| `cwd` 首现 | 99.6% 在前 5 行 | 445/445 |
| 最后一条 `timestamp` | 92% 就是最后一行 | 445/445 |
| `custom-title` | 散布全文，但最后一条在末尾附近 | 40/40 |
| `ai-title` | 同上 | 91/91 |

**消息计数**（用于 3.5 的「对话次数 ≥10」过滤）需要全量扫描，但采用**早停**：
单文件数满 10 条真实用户消息即停止读取该文件。

> **实测机制注（2026-08-27 双探针）**：短会话上 `claude -c` 续接是**同一文件追加**
> （parentUuid 跨运行链），不新建文件；历史数据中的同标题多文件（如「在线设计文件」19 个文件）
> 是**共享继承标题的独立会话**——文件之间无任何跨文件 parentUuid 引用、无 summary/compact 记录，
> 标题相同源于 custom-title 继承（用户 `/rename` 一次，后续新会话全部带上同名）。
> 因此：**每个 jsonl 文件 = 一个独立可 resume 的会话，消息数按单文件计，不做聚合求和**。
> 早停安全（单文件数满 10 即停，无需读全量确认聚合值）。

实测耗时（真实口径，排除 isMeta 与 tool_result 回传）：**3.18 秒**，读取量 252MB → 102MB。
user 消息识别规则：`type=user` 且非 `isMeta` 且 `message.content` 为字符串或含 `text` 块。

读尾部必须用 seek 从后往前取行，不能全量 readlines（最大单文件 22 MB）。
JSON 解析必须用 `[System.Text.Json.JsonDocument]` 流式（169k 行/秒，低内存），**不能**逐行 `ConvertFrom-Json`（21k 行/秒且约 1.2KB/对象，会 OOM）。

> PowerShell 实现坑：`TryGetProperty($name, [ref]$var)` 的 ref 变量必须先类型化为
> `[System.Text.Json.JsonElement]::new()`，传未类型化的 `$null` 会因无法绑定 `JsonElement&`
> 重载而每行抛异常被静默跳过（本调研两次踩坑）。

### 3.3 排除规则

| 排除对象 | 判据 | 依据 |
|---|---|---|
| agent 子会话 | 文件名以 `agent-` 开头 | 占 52%（233/446）。`isSidechain=true` 的记录 100% 落在这些文件内，用文件名判断即可 |
| workflow 日志 | 文件名 `journal.jsonl` | 无 cwd、无会话记录 |
| worktree 临时区 | 路径含 `.claude/worktrees/` | 工具的隔离工作区，不是用户任务（全库 17 个残留） |
| 备份副本目录 | 会话文件路径含 `ConfigBackup` | 会话副本（`E-----ConfigBackup` 等），不排除会同 cwd 重复计数且 mtime 失真（发现 16 的 5 个偏差文件就在这里） |
| 已删除的目录 | `Test-Path` 为假 | 38 个失效路径（含上面的 worktree 残留） |

### 3.4 字段提取规则

- **cwd**：取文件内**最后一条**记录的值。13 个文件的会话中途 cwd 变了（`/add-dir`、中途 cd、worktree 切换），最后一条代表会话结束时所在目录
- **最近活动时间**：取文件内最后一条 `timestamp`（UTC，展示时 +8h）
- **标题**：取最后出现的 `custom-title`，无则最后出现的 `ai-title`，都无则空

**不能用文件 mtime 代替 timestamp 排序**：ConfigBackup 目录下 5 个被复制过的文件，mtime 偏差 66-187 小时，会严重错排。

### 3.5 聚合成列表项

**前置：消息数过滤**（每个 jsonl 文件 = 一个独立会话，消息数按单文件计，见 3.2 机制注）：

- **文件夹项永不因消息数消失**：每个存在的目录至少保留一个快速入口
- **手动命名（custom-title）的会话同样受 ≥10 条阈值约束**（2026-08-27 用户修订：小于 10 次的会话哪怕手动命名意义也不大）。resume 目标取组内 ≥阈值的文件里最新的；整组 <阈值 → 不保留
- **自动命名（ai-title）的会话**：≥10 条的里面**每个目录只保留最新一个，且仅作保底**——目录已有手动命名项（无论该项是否存活）时不再显示自动命名项
- **无标题会话**：不算「保留一个」的候选（没有可显示的名字）；但参与「文件夹副标题」和「最近活动时间」的计算
- **副标题**：= 最近会话的标题；最近会话无标题时**留空**（实测 14/31 目录如此。不回退旧标题——副标题必须与 `-c` 实际接续的会话一致，宁缺勿假）

**会话项的 resume 目标文件**（关键，实测发现的坑）：同 (cwd, title) 下可能有多个文件
（标题继承），**取 ≥10 条阈值的文件里最新的**——直接取最新文件会踩中
`/clear` 空壳：链尾文件只有 8 行，开头就是 `/clear`，resume 进去是空会话；
碎片文件（1-2 条）同样无意义。整组无 ≥阈值 文件 → 该会话项不保留。

两类列表项：

**文件夹项**（约 31 个）：按 cwd 分组，每组一项。
- 显示名 = 目录名
- 副标题 = 该目录下**最近**会话的标题（自动或手动命名都算，无标题则空）
- 时间 = 该目录下最近的活动时间
- 执行 `-c`

副标题取「最近会话的标题」而非「最近的自动标题」，是为了让显示与行为一致 —— 回车执行 `-c` 接的就是最近那个会话，副标题显示的就该是它。代价是当最近会话正好是手动命名的时，副标题会与下方缩进项同名，这个视觉冗余是可接受的。

**会话项**（约 8 个手动命名；保底自动项当前数据下为 0 个）：缩进显示在所属文件夹下。
- 手动命名项：显示名 = 标题，执行 `--resume <session-id>`（sessionId 取该标题下 ≥10 条文件里最新的；整组 <10 条不保留）
- 自动命名项：仅当目录无任何手动命名项时，取 ≥10 条中的最新一个作保底入口

自动命名项一个目录只留最新的一个：它是对「回到这个目录最近一次在干的事」的精确入口，
与文件夹项的 `-c` 语义一致但更可控（`-c` 永远接最新，而列表里能明确看到将恢复哪个标题的会话）。
其余自动命名会话（`git status概览`、`Review pasted text`、`查看后台运行任务`）全部不进列表。

### 3.6 排序

文件夹之间按最近活动降序；会话项紧跟自己的文件夹，组内也按时间降序。

不用纯时间混排：会话项是文件夹的衍生项，混排会把同一文件夹的会话打散到列表各处，缩进项飘在无关位置很困惑。

### 3.7 输出结构

```powershell
[pscustomobject]@{
    Kind      = 'Folder' | 'Session'
    Path      = 'E:\个人\PersonalAITaskCenter\工具\管理_sub2api'
    Name      = '管理_sub2api'      # 文件夹项=目录名，会话项=标题
    Subtitle  = '账号3244请求头覆写'  # 仅文件夹项
    TailPath  = '工具/管理_sub2api'  # 动态级数，见 4.2
    LastActive= [datetime]           # 本地时间
    SessionId = '32c8229f-...'       # 仅会话项
    GroupKey  = 'E:\...\管理_sub2api' # 用于聚合排序
    UserMsgs  = 113                   # 逻辑会话聚合消息数（仅会话项）
}
```

## 4. 界面层

### 4.1 布局

**未输入时**（搜索框居左显示淡色占位提示，右侧显示总数）：

```
搜索> 输入关键词，按Enter过滤                        共 27 项

❯ 管理_sub2api    账号3244请求头覆写   1小时前   工具/管理_sub2api
    └ 账号调优                        2天前
    └ 签到                            2天前
    └ codex伪装                       3天前
  PersonalAITaskCenter  git status概览  6天前   个人/PersonalAITaskCenter
  写日志            日志模板整理        昨天     工作/写日志
  ↓ 还有 15 项

  ↑↓ 选择   回车 启动   Esc 取消
```

**输入过滤词后**（占位提示消失，右侧变为「过滤后数/总数」）：

```
搜索> sub                                          12/27

❯ 管理_sub2api    账号3244请求头覆写   1小时前   工具/管理_sub2api
  PersonalAITaskCenter  git status概览  6天前   个人/PersonalAITaskCenter
  ↓ 还有 10 项

  ↑↓ 选择   回车 启动   Esc 取消
```

- 主体列：文件夹名（会话项则缩进 + `└` + 标题）
- 副标题列：仅文件夹项，显示最近会话标题
- 时间列：相对格式
- 路径列：淡色（`ESC[90m`），显示尾部 2 级，不显示全路径
- 搜索行：左侧输入区（空时显示淡色占位符「输入关键词，按Enter过滤」，有输入时显示输入内容）；右侧计数区——未过滤时 `共 N 项`，过滤后 `M/N`（M = 过滤命中数，N = 总数）
- 计数与滚动范围共用：滚动窗口右上角的 `1-12/27` 中的 27 即当前过滤后的条目总数

只渲染窗口能装下的行数，方向键移到边缘时滚动。

### 4.2 路径尾部级数动态调整

默认显示尾部 2 级。若有其他项的尾部 2 级完全相同，则给冲突的这几项各多显示一级，直到能区分。只影响冲突项，其他项保持简短。

实例：`0A_参考源码/源代码仓库/sub2api` 和 `0A_参考源码/源代码理解/sub2api` 显示 2 级会变成两个一样的 `…/sub2api`，需要 3 级。

### 4.3 时间格式

`刚刚`（<5 分钟）/ `N分钟前` / `N小时前` / `昨天` / `N天前`（≤7 天）/ `08-05`（>7 天转绝对日期）

### 4.4 搜索过滤

匹配「文件夹名 + 会话标题 + 全路径」三者的并集，**子串匹配**（不区分大小写）。

全路径参与匹配（尽管不显示），让 `工具` 这种分类词能筛出该分类下所有任务。

**不做** fzf 式跳字符模糊匹配，**不做**拼音首字母匹配 —— 拼音需内置约 20KB 汉字转拼音表，列表仅约 50 项配合方向键足够用，是明显的复杂度增量。

某会话项命中时，把它的父文件夹一起显示作为上下文。

### 4.5 中文输入法的硬限制

Windows Terminal 的 IME 组字过程（拼音字母、候选窗）**不经过控制台输入缓冲**，`ReadKey` 读不到。只有提交候选词时，最终的中文字符才作为按键事件进来。

**后果**：英文数字可以逐键实时过滤；中文只能在 IME 提交后才触发一次过滤。这是终端与 IME 的机制决定的，任何工具（包括 fzf）在 Windows 上都一样。

**缓解**：`cct <英文关键词>` 参数形式绕过 IME；Enter 语义设计为「确认当前选择」，使 IME 提交产生的额外 Enter 事件恰好符合直觉（提交的字符先进输入框，随后 Enter 确认）。

### 4.6 终端交互技术要点

全部已在本机 pwsh 7.6.5 实测通过：

| 项目 | 方案 |
|---|---|
| 按键读取 | `[Console]::ReadKey($true)`。方向键 KeyChar 是 `\0`，必须用 `.Key` 判断 |
| Ctrl+C | 需 `[Console]::TreatControlCAsInput = $true`，仅在按键循环期间开启（开启期间耗时操作无法被 Ctrl+C 中断） |
| 中文宽度 | .NET **无**内置 East Asian Width，`StringInfo` 无用。必须手动判 Unicode 区间，用 `[System.Text.Rune]` 遍历（正确处理 emoji 代理对与零宽字符） |
| ANSI 转义 | 直接写 `[char]27` 转义串，**不用** `$PSStyle`（重定向时会被剥离） |
| 防闪烁 | 缓存上一帧行数组，逐行 `-cne` 比较只重绘变化行。**不用** `ESC[2J` 全清 |
| 退出恢复 | `ESC[?1049h` 进备用屏幕，`ESC[?1049l` 退出并恢复原终端内容。必须在 `finally` 里恢复 |
| 淡色 | `ESC[90m`（Campbell 配色下 `#767676`）。选中行若用 `ESC[7m` 反白则不加淡色（会看不清） |

## 5. 执行层

### 5.1 执行顺序（关键）

```powershell
Set-Location -LiteralPath $item.Path   # 1. 必须先切目录
# 2. 再启动 claude
```

**实测证据**：在 `C:\...\Temp` 下 resume 一个属于 `E:\...\CC-Switch用量提取代码` 的会话，问它工作目录，回答是 `C:\Users\gt\AppData\Local\Temp`。

> `--resume` **不会**自动回到会话的原始目录，它用你当前所在的目录。顺序颠倒会让恢复的会话跑在错误目录下。

### 5.2 启动命令

- **文件夹项**：`claude --dangerously-skip-permissions -c`（等同用户现有的 `claude-dc`）
- **会话项**：`claude --dangerously-skip-permissions --resume <session-id>`

实测 `-c` 在无历史的空目录会优雅降级为新会话（退出码 0），所以对全新目录也安全，不需要「先判断有没有历史」的分支。

命令模板可在配置文件中修改。

### 5.3 退出后的目录

**留在任务目录**。符合 `cd` 的直觉（主动切过去了就该在那儿），退出 claude 后可以接着 `git status`、看文件。想回原处用 `cd -` 或 `Pop-Location`。

### 5.4 错误处理

| 场景 | 处理 |
|---|---|
| 目录不存在（列表快照后被删） | 报错，留在原地，不启动 |
| `--resume` 失败（会话损坏/被清理） | **打印一行提示**（「该会话无法恢复，已改为接续最近会话」）后降级为 `-c` |
| `claude` 不存在或启动失败 | 直接透出原始错误 |

resume 失败不静默降级：静默会让用户困惑「我明明选了『账号调优』怎么进了别的会话」。

### 5.5 边界行为

- **列表为空**（首次使用、无任何会话历史）：直接打印提示退出，不进交互界面
- **只有一项**：仍显示界面等确认，**不自动启动** —— 避免「只是想看看有什么任务」时意外开会话
- **`cct <关键词>` 唯一命中**：同上，仍需回车确认

## 6. 配置

`~/.cct/config.json`，首次运行自动生成带默认值：

```json
{
  "launchCommand": "claude --dangerously-skip-permissions -c",
  "resumeCommand": "claude --dangerously-skip-permissions --resume {sessionId}",
  "excludePathPatterns": [".claude/worktrees/", "ConfigBackup"],
  "maxVisibleRows": 0,
  "minUserMessages": 10
}
```

`maxVisibleRows: 0` 表示自适应窗口高度。`minUserMessages` 是会话消息数阈值（逻辑会话聚合值 < 此数的自动命名会话不保留；手动命名不受影响，文件夹项永不因此消失）。

不放项目目录：这是个人配置，不该跟着代码走版本控制。用 JSON 而非 psd1：便于手改，也便于以后换语言重写。

## 9. 测试策略

**测试框架**：本机只有 Windows 自带的 Pester 3.4.0，语法与现代 Pester 5 差异很大（`Should Be` vs `Should -Be`、无 `BeforeAll` 作用域隔离等）。

方案：实现前先 `Install-Module Pester -Scope CurrentUser -Force -SkipPublisherCheck` 装 Pester 5，用现代语法。若安装受阻，退回自写极简断言函数（本项目测试都是纯函数的输入输出比对，不需要框架特性）。

**可直接单元测试的纯逻辑**（优先 TDD）：

- `Get-DisplayWidth`：中文 4、全角 8、emoji 2、肤色修饰符 0、组合重音 0、零宽空格 0
- 路径尾部级数动态调整：给定冲突路径集合，验证输出能区分
- 相对时间格式化：给定时间差，验证输出文案
- 搜索过滤：给定任务集合与查询词，验证命中结果与顺序
- 聚合排序：给定原始会话数据，验证文件夹聚合与组内排序
- 字段提取：给定构造的 jsonl 内容，验证 cwd 取最后一条、标题优先级、排除规则
- **消息数过滤与聚合**：给定多个共享标题的独立会话文件（模拟标题继承），验证单文件计数、
  ≥10 阈值、手动命名全保留、自动命名每目录留最新一个且仅作保底、无标题不算候选、
  文件夹项永不消失、副标题取最近会话且无标题留空、resume 目标取最新有实质内容的文件
  （链尾是 `/clear` 空壳时跳过它）

**需要真实数据验证的**：

- 头尾 50 行提取在全库 446 个文件上的命中率（已验证 100%，实现后回归）
- 完整扫描耗时（含消息计数早停，目标 4 秒内，实测 3.18 秒）

**手工验证的**（终端交互无法自动化）：

- 方向键移动、滚动、Esc 取消
- 中文对齐效果
- 退出后终端内容恢复
- 实际启动 claude 并确认工作目录正确

## 10. 已知取舍

| 取舍 | 代价 | 理由 |
|---|---|---|
| 只读会话历史，不扫磁盘 | 全新任务首次仍需手动 cd 一次 | 零配置；29 个真实任务目录没有 CLAUDE.md，扫描反而会漏 |
| 消息数 ≥10 过滤 + 每目录自动命名只留最新 | 未到 10 条的真实会话不会单独成项，只能靠文件夹 `-c` 进入 | 噪音过滤（实测砍掉 `git status概览` 等全部琐碎项）；文件夹项永不消失保证任何目录都有快速入口 |
| 不做拼音匹配 | 中文过滤需等 IME 提交 | 约 50 项配合方向键够用；拼音表是明显的复杂度增量 |
| 不做缓存 | 每次启动重新扫描（含消息计数约 3 秒） | 早停已把读取量压到 102MB/3.18 秒，无状态实现更可靠 |
| 必须改 profile | 用户需手动粘贴一行 | 硬约束：子进程改不了父 shell 的目录 |
